## Production boundary

Production currently contains private Ersomha content (1400 active concepts),
the standalone App Store support page, and live-only policy/Studio/moderation
variables. The public repository's generic Wrangler deployment does not yet
preserve all of these; its bank has 1200 concepts. The new online protocol also
needs a coordinated main/rooms rollout. Do not use this integration as evidence
that the generic production deployment is ready.

After the reviewed PR head passes validation, the merge commit is tagged
`[skip ci]` to skip this one automatic deployment while leaving automatic builds
enabled. It also skips duplicate GitHub push checks for the merge commit;
validation evidence belongs to the exact PR head, not an unexecuted main run.
Verify the merged tree and unchanged live deployments independently afterward.

Workers support for the per-commit marker is confirmed in the
[official Cloudflare discussion](https://github.com/cloudflare/workers-sdk/discussions/13216).
The [GitHub skip documentation](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs)
describes the separate Actions behavior. This marker is not a production
pipeline repair and must not be added to the reviewed PR head itself.

Badeeha uses the on-device question bank and the host's judgment; this remains a
trusted social game rather than a cheat-resistant ranked or prize competition.
