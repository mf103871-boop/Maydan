# الأصدقاء والمحادثات — التشغيل والاختبار

الرابط المعتمد هو [ميدان على maydan-game](https://maydan-game.mf103871.workers.dev). هذا دليل تشغيل للشيفرة الحالية، ولا يُثبت وحده نشر الميزة أو تطبيق ترحيل الإنتاج. إعداد الحسابات في [ACCOUNTS.md](ACCOUNTS.md).

## ما تدعمه النسخة

- صفحة `#/friends` للبحث بالاسم أو رمز الصديق، وإرسال الطلبات وقبولها ورفضها وإلغائها، والحظر وإلغائه.
- محادثة نصية بين صديقين بعد القبول، مع سجل محفوظ في الخادم، ورسائل معلّقة وإعادة محاولة، وتعديل وحذف رسالة المرسل، وعدّاد غير المقروء وإيصال قراءة ومؤشر كتابة.
- حذف الرسالة يفرّغ النص للطرفين ويُبقي إشارة الحذف. فك الحظر لا يعيد الصداقة تلقائيًا؛ بعد قبول طلب جديد تعود المحادثة السابقة.
- الإشعارات داخل التطبيق المفتوح فقط. لا توجد إشعارات نظام أو Push، ولا صور أو ملفات أو تسجيلات صوتية أو مجموعات.
- المحادثات ليست مشفّرة من طرف إلى طرف. ينقل الإنتاج البيانات عبر HTTPS/WSS ويحفظ النصوص في D1.

البحث بالاسم أو رمز `MDN-…` يعيد حتى 20 نتيجة ويحتاج حرفين على الأقل. لا يُعاد البريد الإلكتروني ضمن الملف العام. الحضور وآخر نشاط يظهران للأصدقاء المقبولين فقط.

## التشغيل المحلي الحقيقي

يتطلب المشروع Node.js 22 أو أحدث واعتماديات `package-lock.json`. نفّذ من جذر المستودع:

```sh
npm ci
npm run build:cloudflare
node tests/e2e/social.mjs
```

البناء يضبط API على الأصل نفسه. يشغّل E2E العامل الفعلي `server/full-worker.mjs` داخل Miniflare/workerd مع D1 وDurable Objects وWebSocket، ويطبق الترحيلات في قاعدة مؤقتة. يختبر حسابين منفصلين عبر Playwright بقياسي هاتف وسطح مكتب، ثم يغلق البيئة ويحذفها. لا يستعمل قاعدة الإنتاج.

على Windows يستخدم السكربت Chrome من مساره المعتاد؛ يمكن تحديد مسار آخر عبر `CHROME_PATH`. على الأنظمة الأخرى جهّز Chromium الخاص بـPlaywright عند الحاجة:

```sh
npx playwright install chromium
```

تُكتب صور المحادثة الاختبارية في `.wrangler/social-e2e/conversation-mobile.png` و`conversation-desktop.png`. يحتوي الاختبار على تسجيل دخول تجريبي داخل بيئته المؤقتة فقط. لا تنقل `AUTH_DEV_FAKE` أو قيم الاختبار إلى إعدادات النشر، ولا تطبع رموز الجلسة أو التذاكر أو ملف `.dev.vars` ضمن الأدلة.

`server/local.mjs` لا يربط `SOCIAL_HUB`، وترد تذاكره بـ`503 SOCIAL_UNAVAILABLE`. استخدم Miniflare/Playwright للتحقق من الميزة كاملة؛ ظهور بيانات REST وحده لا يثبت نجاح الاتصال أو الحضور.

تغطية E2E في `tests/e2e/social.mjs`: طلب الصداقة وقبوله، وصول الرسالة والعدد غير المقروء وإيصال القراءة، مؤشر الكتابة، تعديل الرسالة والرد والحذف، بقاء السجل بعد إعادة التحميل، الحظر وإلغاؤه، وعدم تجاوز عرض الهاتف أو سطح المكتب. وجود السكربت يصف التغطية؛ راجع نتيجة تشغيله الفعلية ولا تفترض نجاحه من هذا الدليل.

## النشر على Cloudflare

النشر المستخدم هو `maydan-game`. تستخدم الميزة قاعدة الحسابات عبر `DB`. طبّق [0004_social.sql](../server/migrations/0004_social.sql) **قبل** نشر العامل؛ تنظيف الحساب يعتمد على الجداول الجديدة أيضًا.

ترتيب الإصدار:

1. تحقّق من حساب Cloudflare وقاعدة `maydan-accounts` المقصودين، ومن نسخة احتياطية خاصة قبل الترحيل. لا تحفظ تصدير القاعدة في المستودع أو أدلة عامة.
2. راجع الترحيلات غير المطبقة، ثم طبّقها على D1.
3. انشر `maydan-game` أولًا؛ `wrangler.jsonc` يعرّف `SOCIAL_HUB` بالفئة `SocialHub` وترحيل Durable Object المسمّى `v2-social`.
4. إذا كان نشر `maydan-rooms` المستقل مطلوبًا، انشره بعد `maydan-game`. ربطه في `wrangler.rooms.jsonc` يشير إلى `script_name: "maydan-game"`، ولا ينشئ namespace اجتماعيًا ثانيًا. يجب أن يستعمل العاملان قاعدة D1 نفسها.

```sh
npx wrangler d1 migrations list maydan-accounts --remote --config wrangler.jsonc
npm run db:migrate
npm run cloudflare:check
npm run cloudflare:deploy
```

هذه أوامر نشر فعلية عند تنفيذها؛ `cloudflare:check` فحص تجريبي فقط. ربط `maydan-rooms` المشترك قدرة اختيارية مجهّزة في الإعدادات، وليس النشر المستخدم. إذا احتجته، نفّذ `npm run rooms:check` ثم `npm run rooms:deploy` بعد نشر `maydan-game`. مشاركة `SOCIAL_HUB`، إلى جانب D1، تمنع فصل حضور الأجهزة وإشعاراتها بين عاملين.

بناء GitHub Pages الحالي لا يفعّل API: `online.config.json` فارغ. لتوصيل واجهة أخرى اختر عنوان API عند البناء، واسمح بأصل تلك الواجهة في `EXTRA_ORIGINS` للعامل الكامل. مثال PowerShell، دون أسرار:

```powershell
$env:MAYDAN_ROOMS_URL = 'https://maydan-game.mf103871.workers.dev'
npm run build
Remove-Item Env:MAYDAN_ROOMS_URL
```

هذا مثال إعداد؛ لا يعني أن GitHub Pages موصول حاليًا. `npm run build:cloudflare` يختار `same-origin` تلقائيًا.

لا توجد أسرار اجتماعية جديدة. تبقى أسرار الحساب ومزوّديه في Cloudflare Secrets؛ لا تُضاف إلى العميل أو SQL أو سجل الاختبار. تُعالج مسارات الاتصال المباشر قبل REST الاجتماعية في `server/worker.mjs`، ويُصدّر العامل الكامل `SocialHub` أيضًا.

إذا غاب `SOCIAL_HUB`، يستمر REST وتصبح الإشعارات best-effort بلا بث، وترد `/live-ticket` و`/socket` بـ`503 SOCIAL_UNAVAILABLE`. إذا غاب `DB` فلا تتوفر الميزة. فشل البث بعد حفظ رسالة أو طلب لا يحوّل الحفظ الناجح إلى خطأ لدى العميل.

## عقد API

كل مسارات REST التالية تبدأ بـ`/api/social`، وتتطلب جلسة الحساب في ترويسة `Authorization: Bearer <session>` وأصلًا مسموحًا. أجسام الكتابة JSON. الردود بلا تخزين مؤقت، والأخطاء بالشكل `{"error":"CODE"}`. يجب التقاط ترويسة `x-maydan-session` عند تدوير الجلسة؛ `AccountProvider.requestAuthenticated` يفعل ذلك ويعالج انتهاء المصادقة.

| الطريقة والمسار | الجسم أو الاستعلام | النتيجة الأساسية |
| --- | --- | --- |
| `GET /me` | — | `{user}`: المعرّف والاسم والرمز العام |
| `GET /search` | `?q=` اسم أو رمز | `{users}` مع حالة العلاقة |
| `GET /friends` | — | `{friends}` مع الحضور وآخر نشاط ومعرّف المحادثة |
| `GET /requests` | — | `{incoming,outgoing}` |
| `POST /requests` | `{userId}` | `{request}` |
| `POST /requests/:id/accept` | — | `{conversationId}`؛ المستلم فقط |
| `POST /requests/:id/reject` | — | `{ok:true}`؛ المستلم فقط |
| `DELETE /requests/:id` | — | `{ok:true}`؛ مرسل الطلب فقط |
| `DELETE /friends/:userId` | — | إزالة الصداقة وإغلاق الوصول إلى المحادثة |
| `GET /blocks` | — | `{users}` |
| `POST /blocks` | `{userId}` | حظر وحذف علاقة الصداقة أو الطلب |
| `DELETE /blocks/:userId` | — | إلغاء الحظر الذي وضعه صاحب الجلسة |
| `POST /reports` | `{userId,reason,messageSeq?}` | `{ok:true}` |
| `GET /conversations` | — | `{conversations}` مع آخر رسالة والأعداد ومؤشرات القراءة |
| `GET /conversations/:id/messages` | `before` أو `after`، و`limit` | صفحة رسائل ومؤشرات الصفحات والقراءة |
| `POST /conversations/:id/messages` | `{text,clientId}` | `{message}` |
| `GET /messages/:seq` | — | `{message}` للمشارك المصرح له |
| `PATCH /messages/:seq` | `{text}` | `{message}`؛ المرسل فقط |
| `DELETE /messages/:seq` | — | `{message}` بنص فارغ وتوقيت حذف؛ المرسل فقط |
| `POST /conversations/:id/read` | `{seq}` | `{readSeq}` لا يتراجع |
| `POST /live-ticket` | — | `{ticket,userId,expiresAt}` |
| `GET /socket` | `?userId=&ticket=` مع WebSocket Upgrade | اتصال مباشر |

التوقيت بالمللي ثانية والترتيب والصفحات بواسطة `seq`. الصفحة الافتراضية 50 وسقفها 100؛ لا تجمع `before` و`after`. يعيد الخادم `nextBefore,nextAfter,hasMore,readSeq,peerReadSeq` مع الرسائل.

أعد المحاولة غير المؤكدة بـ`clientId` والنص الأصلي نفسيهما؛ لا تُنشأ رسالة مكررة، واختلاف الحمولة يرد بـ`409 CONFLICT`. الحظر من أي طرف أو إزالة الصداقة يمنع الوصول إلى المحادثة ورسائلها. أغلب محاولات الوصول غير المصرح به ترد بـ`404 NOT_FOUND`.

حدود الخادم تشمل نص رسالة حتى 2000 محرف Unicode، وسبب بلاغ حتى 1000، و10 طلبات صداقة في الدقيقة لكل حساب، و60 رسالة جديدة في الدقيقة، و10 بلاغات في الساعة. توجد أيضًا حدود كتابة عامة لكل حساب وحدود حسب نوع الطلب وعنوان الاتصال. الإلغاء لا يعيد حصة طلب الصداقة، وإعادة إرسال الرسالة المطابقة لا تستهلك رسالة جديدة.

## الاتصال والحضور وعزل الحسابات

تذكرة الاتصال عشوائية، عمرها 60 ثانية، أحادية الاستخدام ومربوطة بالمستخدم والجلسة. يخزّن Durable Object بصمتها ومعرّف الجلسة؛ لا يحمل عنوان WebSocket رمز جلسة الحساب. تُستهلك التذكرة قبل قبول الاتصال، ويُرفض استخدامها المتزامن أو المكرر. الحد 8 تذاكر معلّقة و16 اتصالًا للحساب.

يرسل العميل `{"type":"ping"}` كل 20 ثانية ويتلقى `{"type":"pong"}`. يعلن الخادم `{"type":"ready","userId":"…","heartbeatMs":20000}` عند الاتصال. يُكتب `last_active_at` وتُمدد مهلة `online_until` مع كل اتصال أو نبضة؛ الحساب غير متصل بعد 45 ثانية دون نبضة، ويصير غير متصل فور آخر إغلاق مع حفظ آخر وقت نشاط. بقاء جهاز آخر متصل يبقي الحضور. جلسة الحساب وحدها أو فتح تذكرة دون اتصال لا تعني حضورًا.

يُبث `{"type":"refresh","reason":"presence","userId":"…"}` للأصدقاء عند الانتقال بين متصل وغير متصل فقط؛ النبضات المستمرة تحدّث D1 دون بث إضافي. عند إخفاء الصفحة يغلق العميل اتصالها، ويعيد الاتصال والتحديث عند العودة. يوجد تحديث REST كل 30 ثانية ما دامت الصفحة مرئية، حتى مع توفر الاتصال المباشر، لاستدراك إشعار فائت. إعادة الاتصال تتراجع تدريجيًا حتى 30 ثانية.

الأحداث الأخرى هي `refresh` لتحديث القوائم، و`message` مع `conversationId,messageSeq` دون النص؛ يجلبه العميل عبر REST مع فحص الصلاحية. يرسل مؤشر الكتابة `{"type":"typing","peerId":"…","active":true}` دون المسودة. يتحقق الخادم من الصداقة والحظر بالاتجاهين ويضع هوية المرسل بنفسه. الحد القصير ثلاث إشارات `active:true` في الثانية للحساب؛ إشارات التوقف `active:false` تمر فورًا، مع بقاء الحد العام 60 إطارًا خلال عشر ثوانٍ لكل اتصال. يعيد المستقبل فحص العلاقة، ويختفي المؤشر بعد ست ثوانٍ دون تحديث.

يُفحص إلغاء الجلسة وانتهاؤها وحجز حذف الحساب عند الاتصال والنبض والرسائل الواردة وقبل البث الصادر. عند تدوير جلسة طلب التذكرة ترتبط التذكرة بالجلسة الجديدة. حالة العميل وطلباته ومؤقتاته مرتبطة بهوية الحساب؛ عند الخروج أو تبديله تُمسح الحالة ويُغلق الاتصال، ولا تُقبل استجابة متأخرة من الحساب السابق. لا يُحفظ سجل المحادثة في localStorage أو IndexedDB؛ آلية حفظ جلسة تسجيل الدخول نفسها موضحة في دليل الحسابات.

## البيانات والحذف والبلاغات

ينشئ الترحيل جداول `social_profiles, social_friendships, social_blocks, social_conversations, social_messages, social_reads, social_reports, social_limits`. تحتوي البلاغات على معرّفي المبلّغ والمبلّغ عنه والسبب ووقت الإنشاء، ومعرّف الرسالة ونسخة نصها عند اختيار رسالة. لا يتيح API قراءة البلاغات للمستخدمين، ولا يرسلها للطرف المبلّغ عنه.

يمكن الإبلاغ عن رسالة مستلمة حتى بعد الحظر إذا كان المبلّغ مشاركًا في محادثتها وكانت الرسالة غير محذوفة. يحتفظ البلاغ بنسخة النص التي أُخذت وقت تقديمه، وقد تبقى هذه النسخة بعد حذف الرسالة لاحقًا. حذف الرسالة يمسح النص من سجل المحادثة لكنه يُبقي معرّفاتها وتوقيتها وبصمة النص الأصلية اللازمة لمنع تكرار الإرسال. لا توجد مدة حذف تلقائي للرسائل أو البلاغات في مهمة تنظيف الحسابات اليومية الحالية.

حذف الحساب يحذف علاقاته وحظره ومحادثاته ورسائل تلك المحادثات ومؤشرات القراءة وبلاغاته المرتبطة وحدوده وملفه الاجتماعي ضمن معاملة D1 الخاصة بالحساب. بعد ذلك تُطلب إزالة بيانات `SocialHub` بشكل best-effort: إغلاق الاتصالات، مسح بيانات ارتباط الجلسة والتذاكر وحالة التخزين. المسار الداخلي يتحقق أن المستخدم غائب أو محجوز للحذف، ولا يُعرض كمسار API عام. لا تعيد أحداث الإغلاق المتأخرة إنشاء بيانات المستخدم. يعيد الإنذار فحص غياب الحساب، بما في ذلك فحص صيانة للحالة الخاملة بعد 24 ساعة؛ وإذا تعثر مسح التخزين يُجدول تكراره بعد دقيقة. قد تبقى نسخة خارج الخدمة نسخها الطرف الآخر أو التقط لها صورة.

## مراجعة البلاغات بواسطة المالك

تُحفظ البلاغات في D1 ولا توجد لوحة إدارة أو بريد تلقائي أو حالة «تمت المراجعة» في هذه النسخة. يجب أن يراجع مالك الخدمة القاعدة دوريًا. قناة التواصل الحالية هي `SUPPORT_EMAIL` في `src/shared/account/config.js`، وتظهر في صفحات الخصوصية والشروط: [mf103871@gmail.com](mailto:mf103871@gmail.com). لا ترسل للمستخدم رمز جلسة، ولا تطلبه منه، ولا تنسخ أدلة البلاغ إلى تقرير عام.

استخدم جلسة Cloudflare مخوّلة على القاعدة المقصودة. الاستعلامات التالية **للقراءة فقط**، وتعمل في D1 Console أو عبر `wrangler d1 execute ... --command`. ابدأ بملخص محدود، ثم افتح نص البلاغ المطلوب فقط:

```sql
SELECT id, reporter_id, reported_id, message_seq,
       datetime(created_at / 1000, 'unixepoch') AS created_utc
FROM social_reports
ORDER BY created_at DESC, id DESC
LIMIT 50;
```

```sql
SELECT id, reporter_id, reported_id, message_seq, message_text, reason,
       datetime(created_at / 1000, 'unixepoch') AS created_utc
FROM social_reports
WHERE id = 'REPORT_ID';
```

استبدل `REPORT_ID` بمعرّف بلاغ من الملخص؛ لا تستعمل مدخلًا خامًا من مستخدم لبناء SQL. يعرض الاستعلام الثاني نصًا خاصًا فلا يُحفظ في سجلات عامة أو صور أدلة. مثال ملخص عددي لا يعرض النصوص:

```sh
npx wrangler d1 execute maydan-accounts --remote --config wrangler.jsonc --command "SELECT COUNT(*) AS reports FROM social_reports;"
```

لا يوجد في هذه الميزة إجراء إداري جاهز لتعليق حساب أو إغلاق بلاغ. وثّق قرار المراجعة في قناة الإدارة الخاصة المعتمدة، وتواصل عبر الدعم عند الحاجة؛ لا تُجرِ تعديلات عشوائية على جداول المستخدمين أو الجلسات أو العلاقات لمعالجة البلاغ. إرسال بلاغ ناجح يعني أنه حُفظ للمراجعة، ولا يعني أن إجراءً إداريًا اتُّخذ تلقائيًا.
