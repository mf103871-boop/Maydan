# واجهة استوديو ميدان

الاستوديو يحرر وثيقة تصميم محدودة الحقول؛ لا يرسل JavaScript أو HTML أو CSS حرًا. قواعد اللعب والمشتريات والصلاحيات مستقلة عن وثيقة التصميم. المسودة والإصدارات غير المنشورة خاصة بالمحررين، ولا يغيّر الحفظ واجهة اللاعبين.

## الإعداد والوصول

- طبّق الترحيل التراكمي `0012_design_studio.sql` على قاعدة D1 الموجودة بعد أخذ النسخة الاحتياطية المعتادة.
- `DESIGN_EDITOR_USER_IDS`: معرفات حسابات ميدان المسموح لها بالتحرير، مفصولة بفواصل. القيمة الفارغة تمنع التحرير للجميع؛ لا تُمنح الصلاحية للمشرف أو مدير الشلّة تلقائيًا.
- `DESIGN_PUBLISH_ENABLED=1` يتيح النشر والرجوع العام. تبقى القيمة معطّلة حتى اكتمال تجربة iPhone الفعلية؛ المعاينة الخاصة متاحة دون فتح النشر.
- الصور تستخدم ربط R2 الخاص الموجود `SOCIAL_AUDIO` تحت السابقة `studio-assets/`. لا روابط عامة إلى الحاوية ولا مفاتيح تخزين في العميل.
- الدخول هو جلسة ميدان الحالية `Authorization: Bearer …`. يجب أن يستخدم العميل مسار الطلبات المعتمد الذي يحفظ ترويسة تدوير الجلسة `x-maydan-session`، حتى عند جلب صورة خاصة.
- يبقى تحقق أصل الطلب في العامل. يضاف `x-design-name` إلى ترويسات CORS المسموحة لرفع الصور، واستثناء القراءة العامة لمسار صورة واحد محدد لا يمنح الوصول إلى صور المسودة.

كل رد JSON يحمل `Cache-Control: no-store`. لا توضع الجلسة أو هوية المحرر أو روابط `blob:` في مخزن التصميم المنشور دون اتصال.

## العقود

وثيقة التصميم المشتركة:

```json
{
  "schemaVersion": 1,
  "registryVersion": 1,
  "tokens": {},
  "screens": {},
  "assets": []
}
```

تُقبل معرفات الشاشات والعناصر المسجلة فقط. `assets` قائمة معرفات الصور المعادة من خدمة الرفع. تحتاج إضافة صورة زخرفية إلى إرفاق معرفها في هذه القائمة. التحقق نفسه يعمل في المحرر والخادم وقارئ التطبيق، ويمنع إخفاء العناصر المحمية والأنماط غير المدعومة.

| المسار | الطلب | النتيجة |
|---|---|---|
| `GET /api/design/me` | جلسة موجودة | `{allowed,publishEnabled,previewVersionId}`؛ للمحرر يضاف `{publishedVersionId,publishedRevision}` لاستخدام المؤشر الحالي بعد إعادة الفتح |
| `GET /api/design/draft` | جلسة محرر | `{document,revision,updatedBy,updatedAt}`؛ أول وثيقة قد تكون `null` والمراجعة `0` |
| `PUT /api/design/draft` | `{document,expectedRevision}` | `{document,revision,receipt}`؛ اختلاف المراجعة يعيد `409 CONFLICT` |
| `GET /api/design/versions` | جلسة محرر | `{versions,published:{versionId,revision,updatedAt}}`؛ أحدث 100 إصدار |
| `POST /api/design/versions` | `{name,expectedRevision}` | `201 {version,receipt}`؛ ينسخ المسودة الحالية إلى إصدار ثابت |
| `GET /api/design/versions/:id` | جلسة محرر | `{version:{id,name,document,documentHash}}` |
| `PUT /api/design/preview` | `{versionId}` | `{versionId,receipt}`؛ يختار المعاينة للحساب صاحب الجلسة فقط |
| `DELETE /api/design/preview` | بلا جسم | `{versionId:null,receipt}`؛ يلغي الاختيار الخاص |
| `POST /api/design/publish` | `{versionId,expectedPublished}` | `{versionId,revision,updatedAt,receipt}` |
| `POST /api/design/rollback` | `{versionId,expectedPublished}` | العقد نفسه، مع إيصال نوعه `rollback` |
| `GET /api/design/assets` | جلسة محرر | `{assets}`؛ أحدث 200 صورة جاهزة |
| `POST /api/design/assets` | جسم الصورة الثنائي | `201 {asset,receipt}` |
| `GET /api/design/assets/:id` | جلسة محرر أو صورة منشورة حاليًا | جسم الصورة وMIME؛ الخاص غير المصرّح به يعيد `404` |
| `HEAD /api/design/assets/:id` | الشروط نفسها | ترويسات الصورة دون جسم |
| `GET /api/ui-config?schemaVersion=1&registryVersion=1` | المصادقة اختيارية | `{document,versionId,channel,revision}` |

`expectedPublished` هو **معرف النسخة المنشورة الذي رآه المحرر**، أو `null` قبل أول نشر. لا تُرسل `undefined` ولا رقم المراجعة مكانه. يرفض الخادم الطلب إذا تغيّر المؤشر قبل حفظه. النشر يثبت المؤشر وإتاحة الصور والإيصال معًا في معاملة D1؛ لا ينشر نسخة نصف مكتملة. الرجوع يستهدف إصدارًا ثابتًا موجودًا؛ للعودة إلى الواجهة الأصلية احفظ وثيقة التصميم الافتراضية كإصدار ثم انشرها.

الرد من `/api/ui-config` يكون:

- `preview`: للحساب المخوّل الذي اختار إصدارًا صراحة، دون التأثير على الحسابات الأخرى.
- `published`: النسخة العامة المتوافقة مع نسختي المخطط وسجل العناصر المطلوبتين.
- `default`: `{document:null,versionId:null,channel:"default",revision:0}` عند غياب نسخة متوافقة. يختار التطبيق تصميمه المضمّن ويمسح النسخة المنشورة القديمة من مخزنه.

لا توجد معاملات URL لاختيار معاينة حساب آخر. اختلاف نسخ المخطط، أو تكرار معاملات التوافق، يعيد الافتراضي. المسودة لا تصل إلى هذا المسار.

## رفع الصور وتشغيلها

أرسل `Content-Type` واحدًا من `image/png` أو `image/jpeg` أو `image/webp`. يمكن إرسال الاسم المشفّر بـ`encodeURIComponent` في `x-design-name`. الحد **5 MiB** لكل جسم، و**4096×4096** للبعدين. تُفحص التوقيعات والبنية والأبعاد، وتزال البيانات الوصفية، وتُرفض SVG والصيغ المتحركة المدعومة في هذه الحاويات. لا تستنتج الخدمة MIME من اسم الملف.

```json
{
  "asset": {
    "id": "معرف-الصورة",
    "name": "صورة",
    "url": "/api/design/assets/معرف-الصورة",
    "mime": "image/png",
    "width": 800,
    "height": 600,
    "byteLength": 12345,
    "sha256": "بصمة-المحتوى",
    "createdAt": 0,
    "published": false
  },
  "receipt": { "id": "معرف-الإيصال", "action": "upload_asset", "assetId": "معرف-الصورة", "createdAt": 0 }
}
```

صورة المسودة تُجلب بطلب مصادق عليه وتعرض عبر `blob:` محلي مؤقت. تُحرر الروابط عند الاستبدال أو تبديل الحساب؛ لا تخزن ضمن نسخة منشورة. الصورة متاحة للزائر فقط إذا كانت ضمن الإصدار المنشور **الحالي**؛ الرجوع أو النشر إلى إصدار لا يستخدمها يسحب هذا الوصول. الترويسات `no-store` تمنع تثبيت قرار إتاحة قديم في CDN أو المتصفح. لا يمكن سحب نسخة سبق لشخص تنزيلها إلى جهازه.

يفحص الحفظ والنشر جاهزية جميع الصور. إبطال الجلسة أثناء الرفع يمنع تثبيت الصورة؛ فشل أو تأخر رد D1 بعد نجاح التثبيت لا يحذف جسم صورة محفوظة. قد تبقى بقايا رفع خاصة عند تعذر التحقق من القاعدة، لكنها لا تظهر للزائر أو في قائمة الصور الجاهزة.

تعاد صلاحية قراءة الصورة بعد جلبها من التخزين وقبل إرسالها، لأن الرجوع لإصدار آخر أو سحب صلاحية المحرر أو إبطال جلسته قد يحدث أثناء انتظار التخزين. لا يكفي أن كانت الصورة منشورة عند بداية الطلب.

عند حذف حساب محرر، تحذف معاينته الخاصة وتزال نسبة المسودات والإصدارات والصور والإيصالات إلى معرف حسابه ضمن عملية حذف الحساب نفسها. تبقى وثائق تصميم التطبيق وإصداراتها وملفاتها المشتركة وسجل العمليات منزوع النسبة؛ لا يؤدي حذف الحساب إلى كسر تصميم منشور أو نسخة محفوظة. تخضع الصور الخاصة لشرط النشر الحالي نفسه، ولا يجعل حذف صاحب الرفع أي صورة عامة.

## صور الأسئلة الثابتة في تجربة الويب

`GET` و`HEAD /api/studio/media/<sha256>.webp` يقدمان فقط الصور العامة الأصلية الـ69 المسجلة في `server/design/media-manifest.json`. تتحقق الخدمة من طول الجسم وتوقيع WebP وبصمته قبل الرد؛ البصمة المجهولة تعيد 404. تُخزّن هذه الملفات تحت بادئة إصدار الاستوديو في R2، وتستخدم روابط ببصمة وتخزينًا مؤقتًا ثابتًا. لا تقرأ هذه الخدمة صور المسودات أو البروفايل أو التسجيلات الصوتية، ولا تمنح صلاحيات تصميم أو كتابة.

تحوّل أداة بناء المعاينة مراجع هذه الصور فقط إلى المسار الثابت. تظل بيانات الأسئلة وإجاباتها ومعرّفاتها والبنك المحلي للآيفون كما هي. يسمح عزل المعاينة بقراءة هذا النمط المحدد دون بيانات دخول، وتبقى واجهات الحساب والتصميم الأخرى محجوبة عنها. توثق خطة التسليم بصمات الصور كلها وتفحصها مع ملفات المصدر قبل الرفع، مع إبقاء ملفات الواجهة العامة الأصلية دون تغيير.

## الأخطاء والتحقق

- `401 AUTH_REQUIRED/AUTH_EXPIRED`: الجلسة غير متاحة؛ أعد الدخول بالطريقة الحالية.
- `403 FORBIDDEN/ACCOUNT_SUSPENDED`: لا صلاحية؛ `PUBLISH_DISABLED` يعني أن بوابة التجربة لم تفتح.
- `409 CONFLICT`: تغيّرت المسودة أو النسخة المنشورة، أو أُبطلت الجلسة قبل الكتابة. حدّث الحالة قبل إعادة القرار.
- `400 DESIGN_INVALID/ASSET_NOT_FOUND/IMAGE_INVALID`: وثيقة أو صورة أو مرجع غير صالح.
- `413 IMAGE_TOO_LARGE` أو `INVALID`: تجاوز حد الحجم؛ وثيقة التصميم وجسم JSON محدودان بـ512 KiB.
- `415 IMAGE_TYPE`: نوع صورة غير مدعوم؛ `503 STORAGE_UNAVAILABLE`: ربط التخزين غير متاح.

الحفظ يعيد إيصالًا محفوظًا في `design_actions`. الإصدارات لا تُعدّل بعد إنشائها. اختبارات الخادم تغطي الأدوار، المسودات المتنافسة، نشرًا متزامنًا، عدم تسرب المعاينة بين الحسابات، بوابة النشر، إبطال الجلسات أثناء الكتابة والرفع، عزل الصور وسحبها عند الرجوع، وحدود الصور.

التحقق الآلي والمحاكي لا يثبتان جودة التصميم على iPhone فعلي؛ لذلك يبقى النشر مقفلًا حتى المراجعة البشرية المعتمدة.
