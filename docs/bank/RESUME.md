# استئناف بناء بنك الأسئلة

هذا الملف هو نقطة الاستئناف. يكفي قراءته للمتابعة من حيث توقّف العمل، حتى من
حاوية جديدة أو جلسة جديدة. فرع المتابعة: `codex/continue-question-bank`.
أحدث تقرير تكاملي: [`review-batch-2026-09-08.md`](./review-batch-2026-09-08.md).
الأقسام القديمة في `CONTINUATION.md` سجل تاريخي، وليست عدادات الحالة الحالية.

## أين وصل العمل

اقرأ الحالة الحيّة دائمًا من الأداة لا من هنا:

```bash
node scripts/bank.mjs report      # جدول الفئات الثمانين وخاناتها
node scripts/bank.mjs validate    # يجب أن يكون سليمًا قبل أي التزام
```

الحدود ثابتة ولا تُخفَّض لتمرير فحص: ‏٤٨ سؤالًا لكل خانة من الخانات الخمس
(٢٠٠ / ٤٠٠ / ٦٠٠ / ٨٠٠ / ١٠٠٠)، أي ٢٤٠ سؤالًا لكل فئة.

## دورة الحزمة الواحدة

١. **الكتابة** — تشغيل ورشة بأحد النصّين في `scripts/bank/workflows/`:
   - `bank-plain.js` للفئات العادية.
   - `bank-story.js` لفئات الأعمال (دراما وأفلام وأنمي): يحقن قواعد المحتوى
     في تعليمات الكاتب وفي المدقّق معًا — ٨٠٪ فأكثر عن أحداث داخل العمل،
     ٢٠٪ فأقل عن الممثلين ومحصورة في خانتي ٨٠٠ و١٠٠٠، ومنعٌ باتّ للمخرجين
     والكتّاب والاستوديوهات وسنوات الإنتاج وعدد الحلقات.

   شكل المعطيات:

   ```json
   {
     "newPacks": [{ "id": "...", "name": "...", "scope": "...", "topics": ["..."] }],
     "fill":     [{ "id": "...", "name": "...", "topics": ["..."],
                    "gaps": [{ "p": 200, "need": 20 }] }]
   }
   ```

   `topics` من ستة إلى عشرة مواضيع فرعية. **ملكية الموضوع لا ملكية الخانة**:
   كاتب واحد يملك موضوعًا واحدًا عبر الخانات الخمس كلها. جُرّب البديل (كاتب
   لكل خانة) فبلغ الفقد ٤٢٪ بسبب تكرار الكتّاب بعضهم بعضًا، ونزل إلى ٢٢٪ بهذا
   الترتيب.

٢. **الدمج** — قسّم مخرجات الورشة ثم ادمج:

   ```bash
   node -e "const fs=require('fs');const d=JSON.parse(fs.readFileSync(process.argv[1],'utf8'));
     const ps=d.result?.packs||d.packs;
     fs.writeFileSync('.cache/packs/x-new.json',JSON.stringify({packs:ps.filter(p=>p.mode==='new')}));
     fs.writeFileSync('.cache/packs/x-fill.json',JSON.stringify({packs:ps.filter(p=>p.mode==='fill')}));" <output-file>
   node scripts/bank/merge-pack.mjs  .cache/packs/x-new.json    # حزم جديدة
   node scripts/bank/append-pack.mjs .cache/packs/x-fill.json   # سدّ نواقص
   ```

   الاثنان يُسقطان تكرار نص السؤال داخل الحزمة وعبر البنك كله، وتكرار الإجابة
   داخل الحزمة، بعد التطبيع العربي. تكرار الإجابة بين فئتين تحذير فقط؛ لا
   تُغيّر الإجابة الصحيحة إلى اسم عشوائي لتجاوز التحذير. ويُطبع نقص كل خانة.

٣. **الترتيب والفحص ثم الالتزام**:

   ```bash
   node scripts/bank.mjs sort <id>          # لكل حزمة لمستها
   node scripts/bank.mjs validate
   node scripts/bank.mjs status <id> done   # لمن بلغت ٤٨×٥
   npm test && npm run build
   # راجع الفروق ثم أضف ملفات المهمة المحددة والتزم بها وادفع فرع المتابعة.
   # لا تدمج main ولا تنشر الموقع إلا بطلب صريح لهذه الدفعة.
   ```

## ما تعلّمناه ولا يُعاد اكتشافه

- راجع `docs/bank/retired-qids.json` قبل إنشاء معرّفات جديدة. معرّفات القوالب
  المحذوفة ليست متاحة لإعادة الاستخدام، حتى بعد حذف ملفات الفئات بالكامل.
- الحالات `pending` قد تتضمن ملفات قابلة للعب؛ عدد 240 وحده لا يثبت اكتمال
  جودة الصعوبة أو الفحص البصري. لا تنقل أسئلة سهلة إلى خانة صعبة لإكمال 48.
- `verified: true` الموروثة ليست سجل تحقق جديدًا. احتفظ بمصادر الإضافات
  وسجل الإصلاحات، ولا تصف نجاح الاختبارات بأنه إعادة إثبات كل حقائق البنك.

- **النقص يتركّز في خانة ٢٠٠.** الكتّاب يفرطون في الصعب، والسهل يتصادم مع بقية
  البنك عند إزالة التكرار. اطلب في السدّ ضِعف ما ينقص في هذه الخانة تحديدًا.
- **سقف التوازي داخل الورشة الواحدة هو `min(16, nproc-2)`**، وهو وكيلان اثنان
  على أربعة أنوية. السقف لكل تشغيل لا لكل جلسة، فالتسريع يكون بتشغيل عدة
  ورشات بالتوازي لا بتكبير الورشة الواحدة. الوكلاء ينتظرون الشبكة لا المعالج.
- **الاستئناف يعمل**: إن انقطع تشغيل، أعِد إطلاقه بـ `resumeFromRunId` بالمعطيات
  نفسها فيعود المكتملون من الذاكرة المؤقتة بلا كلفة. أنقذَ هذا ٥٥ وكيلًا من ٥٧
  بعد إعادة تشغيل الحاوية مرة.
- **أخطاء الكشف** (`إجابته … مكشوفة في نص …`) تُصلَح بإعادة صياغة السؤال الآخر،
  لا بحذف السؤال ولا بإضعاف الفحص.

## ما بقي

- **فئات الأعمال** المتبقية: `arabseries` `ramadanseries` `babalhara`
  `syriandrama` `egyptdrama` `turkishdrama` `ertugrul` `squidgame`
  `aot` `deathnote` `demonslayer` `jujutsu` `hunterxhunter` `spacetoon` `cartoon`
  → بـ `bank-story.js`. اجعل نطاق كل حزمة يستثني ما تغطّيه أختها صراحةً.
- **الفئات الدينية الخمس**: `ramadan` `islamiyat` `quran` `seerah` `prophets`.
  تحتاج نسخة ثالثة من النص: قواعد الكتابة الحالية تمنع الدين صراحةً، والمطلوب
  استبدال ذلك المنع بـ «معلومات عامة فقط: أسماء وأماكن وأحداث وأعداد؛ لا فتاوى
  ولا مسائل خلافية ولا مقارنة بين المذاهب».
- **الفئات الخاصة الشكل** (لها `defaultType` في `bank-status.json`):
  `emoji` `hidden` `completeproverb` `beforeafter` `commonbond` `code` `hints`.
  كلٌّ منها يحتاج تعليمات كتابة خاصة بشكل سؤالها، وراجع `docs/bank/SCHEMA.md`
  لحقول كل نوع قبل كتابتها.
- **فئات الوسائط الاثنتا عشرة**: تحتاج ملفات مرخّصة عبر
  `node scripts/media-fetch.mjs`، ومصادرها محصورة في ويكيميديا كومنز وأوبنفيرس
  وأرشيف الإنترنت ووكالات حكومية، وتراخيصها في CC0 والملكية العامة و‎CC BY
  و‎CC BY-SA وحدها. الميزانية: صورة ≤ ٣٠ ك.ب و‎WebP وأطول ضلع ٦٤٠ بكسل،
  صوت ≤ ٥٠ ك.ب و‎MP3 أحادي ٤٨ ك.ب/ث و‎≤ ٨ ثوانٍ، ومجموع الفئة ≤ ٤ م.ب.
- **`childhood` معلّقة**: صور طفولة المشاهير غير قابلة للترخيص. تُحوَّل إلى فئة
  نصية أو تُحذف قبل تنفيذ حزمتها — قرار صاحب المشروع.

## معلّق على صاحب المشروع

- قرار فئة `childhood` ما زال مطلوبًا قبل تنفيذها.
- استئناف تنزيل الوسائط توقف بعد إلغاء موافقة الشبكة؛ راجع
  `review-flags-new.md`. توجد سبع صور مرخصة محفوظة، لا حزمة أعلام مكتملة.
- لا تعتمد على معرّف قديم لـ`main` في المستندات؛ افحص الفرع البعيد عند النشر.
  هذه الدفعة موجهة لفرع المتابعة، وليست تفويضًا لتغيير النسخة المنشورة.
