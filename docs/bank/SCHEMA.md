# بنية بنك «بَديهة» وكيف تستخدمه اللعبة (SCHEMA)

هذا الملف يصف ما يفعله **الكود فعلًا**، لا ما نتمنّاه. كل ادّعاء هنا مأخوذ من
`src/games/badeeha/logic.js` و`App.js` و`keys.js` و`index.js`،
و`tests/badeeha-content.test.js`، و`src/shared/media/resolve.js`،
و`scripts/media.mjs` و`scripts/bank.mjs` و`scripts/lib.mjs`، و`public/sw.js`،
و`src/data/bank-status.json`. كُتب مع الحزمة 0 ويصف الكود كما التُزم به؛
القرارات التي حُسمت فيها مجموعة في القسم 8. القواعد التحريرية في
[`RUBRIC.md`](./RUBRIC.md).

## 1. كيف تختار اللعبة الأسئلة

### الشرائح والأوضاع وأحجام الجولة

- حقل النقاط في السؤال هو `p`، وقيمه 200 / 400 / 600 / 800 / 1000.
- الأوضاع (`MODES` في `logic.js`):

| المعرّف | التسمية في الواجهة | الشرائح |
| --- | --- | --- |
| `family` | عائلي | 200، 400، 600 |
| `standard` | تحدّي | 200، 400، 600، 800 |
| `expert` | خبراء | 200، 400، 600، 800، 1000 |

- أحجام الجولة (`ROUND_SIZES`): 20 أو 30 أو 60 سؤالًا.

### بناء الجولة (`buildDeck`)

1. يجب اختيار **ست فئات بالضبط**، وإلا رُمي خطأ «يجب اختيار ست فئات بالضبط».
2. تُقسَّم الجولة على الفئات الست: `base = floor(total / 6)` وتأخذ أول
   `total % 6` فئات سؤالًا زائدًا. أي: 20 ← 4،4،3،3،3،3؛ 30 ← 5 لكل فئة؛
   60 ← 10 لكل فئة.
3. لكل فئة تُبنى مجموعة لكل شريحة من شرائح الوضع عبر `prioritizedQuestions`،
   ثم تُسحب الأسئلة **بالتناوب على الشرائح**، سؤالًا من كل شريحة في كل دورة،
   بدءًا من إزاحة تساوي **ترتيب الفئة** في الاختيار
   (`tiers[(categoryIndex + cycle + offset) % tiers.length]`). فالفئة الأولى
   تبدأ بـ 200، والثانية بـ 400، وهكذا؛ لذلك تختلف توزيعة الشرائح بين الفئات
   حين لا يقبل نصيب الفئة القسمة على عدد الشرائح.
4. إن نفدت أسئلة شريحة تُتخطّى إلى التالية؛ وإن مرّت دورة كاملة بلا أي سؤال
   جديد ولم يكتمل العدد رُمي خطأ «لا تكفي أسئلة الفئة «…» لهذا الوضع».

### ترتيب الأولوية (`prioritizedQuestions`)

لكل شريحة، تُؤخذ أسئلة الفئة التي `question.p === tier` وتُرتَّب بـ:

1. **غير المُلعَب أولًا** (لا سجل له).
2. ثم **الأقدم لعبًا** (الطابع الزمني الأصغر في السجل).
3. ثم مفتاح عشوائي (`random()`) يُولَّد لكل سؤال في كل بناء.

النتيجة: الأسئلة غير المُلعبة لها الأولوية دائمًا، والتعادل بينها عشوائي في كل
لعبة، ولا يتكرر سؤال عبر الجولات حتى تنفد أسئلة الشريحة غير المُلعبة في تلك
الفئة. الاختيار يعتمد على `p` والسجل فقط؛ **إعادة بناء البنك لا تحتاج أي
تغيير في قواعد اللعبة**.

معرّف السؤال في هذا المنطق هو `qid`، وإن غاب استُخدم بديل
`<category-id>-legacy-<index>` (لكن الفحوص لا تسمح بغيابه، انظر القسم 3).

### سجل ما لُعب (history)

- خريطة `qid → طابع زمني (Date.now())`.
- تُحفظ في `localStorage` تحت المفتاح `maydan:badeeha:question-history-v4`
  (`BADEEHA_KEYS.history` في `keys.js`، ويستورده `App.js` باسم
  `MAYDAN_BETA_KEYS`). المفتاح القديم `maydan-question-history-v4` يُرحَّل مرة
  واحدة بـ `migrateLegacyKeys` (يُنسخ إن كان الجديد فارغًا ثم يُحذف).
- تُكتب في `judgeQuestion` عند الحكم على السؤال، سواء أجاب فريق أم اختير «لا
  أحد»؛ و«تراجع» (`undoLastAction`) يعيد اللقطة السابقة للسجل ويحفظها.
- زر «تصفير السجل» في شاشة الإعداد (`clearQuestionHistory`) يمسحها بعد تأكيد.
- لأن السجل مفتاحه `qid`، فتغيير `qid` سؤالٍ ما يُفقده سجله ويعيده «جديدًا».

### داخل الجولة وحفظ الجلسة

- `used[qid]` خريطة في الذاكرة تمنع إعادة فتح سؤال حُكم عليه (`openQuestion`
  يرفض إن كان `used[question.qid]`)، وعند بلوغها عدد أسئلة الجولة تنتهي
  المباراة. تُحفظ داخل كائن الجلسة النشطة لا في مفتاح مستقل. الثابت
  `STORE_KEY = "maydan-used-questions-v3"` في `App.js` موروث ولا يقرأه شيء.
- الجلسة النشطة تُحفظ تحت `maydan:badeeha:active-game-v2` وفيها الجولة
  **كمعرّفات فقط** (`deckToIds`)، وتُستعاد بـ `idsToDeck(CATS, …)`.
  `isValidSession` يشترط `version: 2`، من فريقين إلى أربعة، ست فئات، وضعًا
  وحجمًا صالحين، وأن يُعثر على **كل** معرّف في البنك وأن يساوي مجموعها حجم
  الجولة. أي `qid` حُذف أو تغيّر يجعل المباراة المحفوظة على جهاز اللاعب غير
  صالحة — سبب إضافي لثبات المعرّفات.

## 2. ملف الفئة

```json
{
  "id": "geo",
  "name": "جغرافيا",
  "icon": "🌍",
  "style": "story",
  "qs": [ { "p": 200, "q": "…", "a": "…", "qid": "geo-200-001" } ]
}
```

| الحقل | إلزامي | ما يفرضه الكود |
| --- | --- | --- |
| `id` | نعم | `^[a-z][a-z0-9]*$`؛ `bank:validate` يوجب مطابقته لاسم الملف `<id>.json`، وهو اسم مجلد الوسائط `media/<id>/`، ويجب أن يكون مسجّلًا في `bank-status.json` |
| `name` | نعم | نص غير فارغ |
| `icon` | نعم | نص غير فارغ (إيموجي) |
| `style` | حسب الفئة | `"story"` لحزم الدراما والأنمي؛ إن كانت الفئة `style: story` في `bank-status.json` وجب وجوده في الملف. يفعّل قواعد أسئلة الإنتاج (القسم 5) |
| `qs` | نعم | مصفوفة أسئلة **مرتّبة** تصاعديًا بـ `p` ثم `qid` (وإلا خطأ «الملف غير مرتّب») |

**التسجيل في `src/data/categories/index.js`:** يولّده `npm run bank:sort -- <id>`
(أو `node scripts/bank.mjs index`) من ملفات المجلد، مرتّبةً بحقل `order` في
`bank-status.json` — وهذا هو ترتيب الفئات في شاشة الاختيار — بالشكل:

```js
import geo from './geo.json' with { type: 'json' };

export const CATS = [geo];
```

`bank:validate` والاختبار يفشلان إن وُجد ملف غير مستورد أو استيراد لملف غير
موجود. الملفات تُدمج في ملف HTML الواحد عند البناء (`loader: { '.json': 'json' }`).

الحالة الراهنة: `src/data/categories/` لا تحوي إلا `index.js` و`CATS = []`؛
الحزم القديمة حُذفت في الالتزام `86aa08d` ويُعاد بناؤها فئةً فئة.

## 3. حقول السؤال

| الحقل | النوع | ما يفرضه الكود |
| --- | --- | --- |
| `p` | عدد | أحد 200/400/600/800/1000 |
| `q` | نص | إلزامي إلا في الأنواع التي يكون فيها الوسيط أو العنصر هو السؤال (`image audio video diff flag zoom pic sound grid odd order scramble common`)؛ ≤ 22 كلمة (`maxQuestionWords`). في أنواع الوسائط يُعرض فوق الملف فقط إن اختلف عن عبارة النوع الافتراضية |
| `a` | نص | إلزامي إلا في `order` و`odd` و`grid`؛ ≤ 6 كلمات (`maxAnswerWords`) |
| `qid` | نص | `bank:validate` يقبل الصيغة الجديدة `<id>-<tier>-<nnn>` (`^[a-z][a-z0-9]*-(200\|400\|600\|800\|1000)-\d{3}$` ويجب أن تبدأ بمعرّف الفئة) أو القديمة 12 خانة ست عشرية؛ فريد عبر البنك. اختلاف شريحة المعرّف عن `p` **تحذير** لا خطأ (مقبول بعد إعادة التصنيف). الاختبارات تقبل الصيغتين |
| `type` | نص | غيابه = سؤال نصي. المعروف للكود والفاحص (20 نوعًا): `image audio video diff truefalse choice scramble complete common hints code emoji order odd grid flag zoom pic sound closest`؛ غيرها خطأ |
| `effect` | نص | لصور `image`: `none` (افتراضي) · `zoom` · `blur` · `silhouette` · `reveal` (12 قطعة تُكشف قطعة قطعة) · `jumble` (12 قطعة مبعثرة بترتيب ثابت مشتق من `qid`) |
| `origin` | نص | نقطة التقريب لـ `effect: "zoom"` ولنوع `zoom`، مثل `"30% 35%"`؛ الافتراضي `"50% 50%"` |
| `spot` | كائن | لـ `diff`: `{ "x": 50, "y": 50, "r": 14 }` نِسَب مئوية 0–100، يظهر عند الكشف |
| `alt` | مصفوفة نصوص | إجابات بديلة؛ الفاحص يوجب أن تكون مصفوفة نصوص غير فارغة إن وُجدت. تظهر للمضيف بعد الكشف: «يُقبل أيضًا: …» |
| `topic` | نص | الموضوع الفرعي؛ **إلزامي في الفئات `done`**، ومنه تُحسب قاعدة 6–10 مواضيع و≤ 25% لكل شريحة |
| `verified` | `true` | **إلزامي في الفئات `done`** |
| `media` | كائن أو مصفوفة كائنات | انظر أدناه؛ الفاحص **يرفض** الشكل النصي المجرد |

### حقول الأنواع الخاصة

| `type` | الحقول | ما يفرضه الفاحص / ما تعرضه اللعبة |
| --- | --- | --- |
| `truefalse` | `a` = `"صح"` أو `"خطأ"` | يُبرَز الصحيح عند الكشف |
| `choice` | `options` (2–4)، و`a` واحد منها | تُعرض العبارة والخيارات ويُبرَز الصحيح عند الكشف؛ المطابقة بعد التطبيع العربي. تُستخدم لـ «قبل ولا بعد» |
| `scramble` | `letters` (اختياري) | إن وُجدت وجب أن تكون حروف `a` نفسها؛ إن غابت تُشتق من `a` |
| `complete` | `q` فيه `___` | |
| `common` | `items` ≥ 3 | القاسم المشترك في `a` |
| `hints` | `hints` من 2 إلى 5 | كل تلميح يخصم 25% (`HINT_COST_PERCENT`) بحدّ أدنى ربع النقاط |
| `code` | `q` = الشفرة، `dir` اختياري (الافتراضي `ltr`)، `hint` اختياري | تُعرض في صندوق `m-code` من اليسار بخط أحادي |
| `emoji` | `q` = الإيموجي، `hint` اختياري | |
| `order` | `items` ≥ 3 بالترتيب الصحيح | تُخلط عند الفتح؛ بلا `a` |
| `odd` | `items` و`odd` = فهرس صالح | بلا `a` |
| `grid` | `grid` و`target` | بلا `a` |
| `flag` | `flag` = وصف العلم (`t`: `h`,`v`,`circle`,`nordic`,`swiss`,`hoist`,`tri`,`kuwait`,`serrated`) | يُرسم SVG |
| `sound` | `sound` = اسم مقطع مُولَّد | `doorbell, alarm, siren, horn, heartbeat, rain, clock, knock, helicopter, morse, sonar, laser` |
| `zoom` / `pic` | `emoji` أو `image` (+ `origin` في `zoom`) | أنواع قديمة بلا ملفات |
| `closest` | `q` رقمي | «الأقرب يأخذ النقاط»؛ لا يُحسب خطفًا |
| `image` | `media` ملف واحد **أو أربعة** | أربعة ← شبكة 2×2 «أربع صور وكلمة» (`FourPics`) |
| `audio` | `media` ملف واحد | |
| `video` | `media` ملف واحد | مشغّل بأدوات تحكّم |
| `diff` | `media` صورتان + `spot` | |

### كائن الوسائط `media`

```json
"media": {
  "src": "geo-200-001.webp",
  "type": "image",
  "title": "…",
  "sourceUrl": "https://commons.wikimedia.org/…",
  "author": "…",
  "license": "CC BY-SA 4.0",
  "licenseUrl": "https://creativecommons.org/licenses/by-sa/4.0/"
}
```

- `resolve.js` و`scripts/media.mjs` يقبلان نصًا أو كائنًا (يُقرأ `src`)؛ أمّا
  `bank:validate` فيوجب **الكائن** بكل حقوله السبعة غير فارغة، ويرفض النص
  المجرد بخطأ «media نص مجرد».
- `license` يُقبل فقط إن كان CC0 أو Public Domain/PD/PDM أو CC BY أو CC BY-SA
  (بأي إصدار)؛ أي NC أو ND أو غير ذلك مرفوض (`isAllowedLicense`).
- `media.type` يجب أن يطابق نوع السؤال (`audio` ← `audio`، `video` ← `video`،
  وإلا `image`).
- حلّ `src`: اسم قصير ← `media/<category-id>/<src>`؛ مسار يبدأ بـ `media/`
  يُترك كما هو؛ `https://…` أو `//…` أو `data:` يُترك كما هو (خارجي: لا يُفحص
  على القرص، ويُصدر الفاحص تحذيرًا).
- نوع الملف يُشتق من الامتداد، ويحسمه `type` السؤال إن كان `audio` أو `video`.
- **الإسناد في اللعبة:** `collectCredits(CATS)` في `src/games/badeeha/index.js`
  يجمع كل كائن `media` له `src` ويضعه في `credits` اللعبة، وتعرضها شاشة «حول»
  في بطاقة «المصادر والتراخيص» (`Credits` في `src/platform/screens/About.jsx`):
  العنوان، المؤلف، الترخيص برابطه، ورابط المصدر.

## 4. الوسائط على القرص

- المجلد: `media/<category-id>/`، وأسماء الملفات بالاتفاق `<qid>.webp` للصور
  و`<qid>.mp3` للصوت (ومتعدد الصور `<qid>-1.webp`…). الكود لا يفرض اسم
  الملف، بل وجوده وامتداده وحجمه.
- الامتدادات المقبولة: صور `webp png jpg jpeg gif avif svg` · صوت
  `mp3 m4a aac ogg opus wav` · فيديو `mp4 webm mov`.
- الميزانيات تُقرأ من `bank-status.json` (`mediaBudget`) ويفرضها
  `bank:validate`: صورة ≤ 30KB، صوت ≤ 50KB (الفيديو بلا حدّ لكل ملف)، ومجموع
  ملفات الفئة ≤ 4MB.
- فهرس النسب `media/<category-id>/_sources.json`: يكتبه `npm run media:fetch`
  لكل ملف جُلب (المصدر، المؤلف، الترخيص، الحجم، تاريخ الجلب) لمراجعة الحقوق؛
  الإسناد الذي تعرضه اللعبة هو كائن `media` داخل السؤال.

### تصحيح ملف بالاسم نفسه

البناء يحسب بصمة محتوى لكل مجلد `media/<id>/` ويحقنها في الحزمة، فتُلحق بعناوين
ملفات ذلك المجلد كـ `?v=<بصمة>`. حين يُستبدل ملف (`media:fetch … --force`)
تتغيّر اللاحقة، فيتجاوز العامل الخدمي نسخته المخزّنة ويجلب الجديد؛ ومخزن
الوسائط لا يُمسح عند تحديث اللعبة كما هو.

### ما يفعله `npm run build`

1. `checkMedia` (في `scripts/media.mjs`) يفحص كل حزمة قبل النسخ، **ويفشل
   البناء** (exit 1) إن أشار سؤال إلى ملف غير موجود، أو إلى امتداد غير مدعوم،
   أو كان `type` `image`/`audio`/`video` وامتداد الملف لا يطابقه. المراجع
   الخارجية تُعدّ ولا تُفحص. (لا يفحص التراخيص ولا الأحجام — ذلك عمل
   `bank:validate`.)
2. ينسخ `media/` إلى `dist/media/` (باستثناء `README.md`) ويطبع عدد الملفات
   وحجم كل حزمة.
3. يختم اسم مخزن العامل الخدمي بمعرّف بناء (`الإصدار-بصمة index.html`)،
   فأي تغيير في المستند يصل للمثبّتين من أول فتحة.

### التخزين في المتصفح (`public/sw.js`)

- ما تحت `/media/` يُخدم من مخزن مستقل `maydan-media-v1`: من المخزن أولًا،
  وإلا من الشبكة ثم يُحفظ.
- عند التفعيل بعد تحديث اللعبة تُحذف كل المخازن **إلا** مخزن التطبيق الحالي
  ومخزن الوسائط، فالوسائط تبقى عبر الترقيات.
- عند بناء اللوحة يُجلب `deckMedia(deck)` في الخلفية، وفي شاشة الإعداد زر
  «حمّل» يرسل رسالة `cache-media` للعامل ليخزّن وسائط الفئات المختارة دفعة
  واحدة.

### ما تعرضه اللعبة

- صورة: في بطاقة السؤال مع المؤثّر؛ **لمسة للتكبير** (صندوق `m-lightbox`،
  يُغلق باللمس أو Escape) متاحة دائمًا للصورة بلا مؤثّر، وبعد الكشف للبقية كي
  لا يُفسد التكبير المؤثّر.
- صوت: زر تشغيل كبير يضغطه المضيف (لا تشغيل تلقائي) وزر «↻ من البداية»؛
  **ثلاث مرات** قبل الكشف (`MAX_AUDIO_PLAYS = 3`؛ تُحتسب المرة عند البدء من
  أوله، والإيقاف المؤقت ثم الاستئناف لا يُحتسب)، وبعد الكشف بلا حدّ.
- فيديو: مشغّل بأدوات تحكّم كاملة.
- المؤقّت يعمل كالمعتاد مع كل الأنواع.

## 5. ملف الحالة `src/data/bank-status.json`

```json
{
  "tierMin": 48,
  "tiers": [200, 400, 600, 800, 1000],
  "maxQuestionWords": 22,
  "maxAnswerWords": 6,
  "mediaBudget": { "imageKB": 30, "audioKB": 50, "categoryMB": 4 },
  "categories": {
    "<id>": {
      "name": "…", "icon": "…", "media": false,
      "status": "pending",
      "counts": { "200": 0, "400": 0, "600": 0, "800": 0, "1000": 0 },
      "doneAt": null,
      "order": 1,
      "style": "story",
      "note": "…"
    }
  }
}
```

- الملف موجود ويضم **80 فئة** (12 وسائط، 23 بـ `style: "story"`)، وكلها
  `pending` بأعداد صفرية. `note` مكتوبة للفئات الدينية الخمس (معلومات عامة
  فقط) ولـ `childhood` (معلّقة لتعذّر الترخيص). `style` و`note` اختياريان؛
  `$comment` تعليق.
- الحدود كلها تُقرأ من هنا في `bank:validate` (مع قيم احتياطية مطابقة) ولا
  تُخفَّض من السكربت.
- `npm run bank:status -- <id> done|pending` يعيد حساب `counts` من الملف
  الفعلي ويضبط `status` و`doneAt` (ISO عند `done`، وإلا `null`).

### ما يفرضه `bank:validate` بحسب الحالة

| الشرط | `done` | `pending` وله ملف |
| --- | --- | --- |
| كل شريحة ≥ `tierMin` (48) | خطأ | — |
| الإجمالي ≥ 24 | (ضمنًا) | خطأ |
| `verified: true` و`topic` في كل سؤال | خطأ | — |
| 6–10 مواضيع، ولا موضوع > 25% من شريحة | خطأ | — |
| `counts` في الملف تطابق الفعلي | خطأ | تحذير |
| `doneAt` موجود | خطأ | — |
| فئة `done` بلا ملف | خطأ | — |

وفي كل الحالات: المعرّفات والأنواع والحقول (القسم 3)، التطبيع ومنع التكرار
(نص السؤال داخل الفئة **وعبر البنك** خطأ؛ الإجابة داخل الفئة خطأ إلا الرقمية
فتحذير؛ الإجابة نفسها في فئتين تحذير مجمّع)، تسريب إجابة في نص سؤال آخر من
الفئة، الترتيب، فئة الوسائط لا تحوي إلا `image/audio/video/diff`، الوسائط
(الكائن، الترخيص، الوجود، الامتداد، الحجم، ميزانية الفئة)، وقواعد
`style: "story"`: أسئلة الإنتاج خطأ، سؤال الممثلين/مؤدّي الأصوات في غير
800/1000 خطأ، ونسبتهم > 20% خطأ.

### ما يفرضه `npm test` (`tests/badeeha-content.test.js` و`tests/bank.test.js`)

`badeeha-content.test.js` يقرأ `bank-status.json`: كل ملف موجود مسجّل فيه؛
الفئة `done` ≥ 48 في كل شريحة وأعدادها تطابق الملف ولها `doneAt`؛ الفئة
`pending` ≥ 24 سؤالًا وبكل الشرائح؛ `qid` بالصيغة الجديدة أو 12-hex القديمة
وفريد؛ نص وإجابة؛ لا تكرار نصي داخل الحزمة؛ لا إجابة مكشوفة في نص آخر؛
و`style: "story"`: أنماط الإنتاج ممنوعة، وأسئلة الممثلين ≤ 20% وفي 800/1000
فقط. و`bank.test.js` يشغّل `validateBank` على البنك كله ويطلب صفر أخطاء،
ويتحقق من أن `tierMin` ما زال 48، إضافة إلى اختبارات وحدة للمدقّق على مستودعات
مؤقتة (تكرار، حدود كلمات، ترتيب، وسائط، تراخيص، دراما).

## 7. ترتيب العمل لكل حزمة

فئة واحدة لكل أمر، بهذا الترتيب:

1. **اختيار الفئة**: `npm run bank:report` لقراءة حالتها وملاحظتها، وقراءة
   ملفها إن وُجد.
2. **مراجعة الموجود**: تحقق من كل معلومة؛ الإصلاح أو الحذف مع تسجيل السبب في
   `docs/bank/removed-<category-id>.md`؛ المعرّفات الموجودة لا تتغير.
3. **المواضيع والتصنيف**: إعلان 6–10 مواضيع (`topic`)، وإعادة تصنيف الصعوبة
   بالإجابة لا بالصياغة (عند التردد الأسهل)؛ شريحة المعرّف تبقى شريحة الإنشاء.
4. **الكتابة**: إكمال كل شريحة إلى ≥ 48 بقواعد الأسلوب، مع `qid` جديد
   `<id>-<tier>-<nnn>`، و`alt` عند الحاجة، و`topic`، و`verified: true`.
5. **الوسائط** (لفئات الوسائط فقط): ملف لكل سؤال من مصدر مسموح بترخيص مقبول،
   ضمن الميزانية، مع كائن `media` كامل الحقول.
6. **الفرز والتسجيل**: `npm run bank:sort -- <id>` (يرتّب ويحدّث `index.js`).
7. **التحقق**: `npm run bank:validate -- <id>` ثم `npm test` ثم
   `npm run build`؛ كلها خضراء دون تخفيض أي حدّ أو لمس أي اختبار.
8. **الإقفال**: `npm run bank:status -- <id> done`، ثم `npm run bank:validate`
   على البنك كله، ثم الالتزام بالصيغة:

```
bank(<category-id>): 5×<n> tiers, +<added> -<removed>, media <m>
```
