# سجل استكمال التصميم ومراجعة الواجهات

هذه الخطوة جرد ومعيار قبول فقط. لا تغيّر محرر Studio أو `registry.js` أو `coverage-map.js` أو مكونات اللعبة، ولا تقرّ أي تصميم أو نشر. تصورات الواجهات الناقصة تُعرض على المستخدم على دفعات قبل تنفيذها. إعادة رسم avatars مأذونة مع حفظ المعرفات والاختيارات والملكية والصور الحقيقية.

## الجرد الحالي وحدوده

شغّل من جذر المستودع:

```sh
node scripts/visual-review-inventory.mjs --output /absolute/delivery/path/inventory.json
node --test tests/visual-review.test.js
```

المشغّل يقرأ جميع هويات السجل الحالي، ويستخرج التصريحات الثابتة لـ`data-design-screen` من JavaScript/JSX عبر AST، ثم يأخذ اتحاد المجموعتين. لا يوجد تأكيد ثابت بأن الإجمالي يجب أن يبقى148؛ أي جذر جديد يزيد نطاق المراجعة تلقائيًا. السلاسل التي تحتوي selectors والتعليقات ليست جذورًا. تحليل JavaScript لا يشغّل المكونات ولا يثبت ظهورها.

مصدر التحليل `src` بامتدادات js/jsx/mjs، باستثناء `src/data` و`src/design`؛ البيانات وسيناريوهات المعاينة ليست واجهات إنتاج جديدة. يُسجل كل ملف مقروء وبصمته. التعبيرات الديناميكية، أخطاء التحليل، ومسارات الفجوات المفقودة تظهر تحت `unknownPaths`؛ لا تُعامل كنجاح. تعريف جذر داخل object props هو تصريح مرشح، لا إثبات وصول المستخدم إليه.

وقت إنشاء السجل كان الأساس143 مشهدًا:39 منصة،39 local-game تتضمن تدريب مافيا،65 غرفة. توجد جذور مستقلة للشروط ولوحة الصانع ودخول اللعبة واسترداد الرمز وخيارات المحادثة. هذه أعداد وصفية؛ الحكم الفعلي هو فرق المجموعات في التقرير المتولد. `registeredWithoutStaticLiteral` قد يتضمن جذورًا مركبة ديناميكيًا، ولا يعني أنها مفقودة من التطبيق.

`VISUAL_REVIEW_GAPS` يعلن عملًا غير مربوط بعد: الإقلاع، إدارة المراجعة، تمارين مافيا، المنافسة، المجتمع، مراجعة المباراة، صندوق البلاغات، استعادة التعطل، وبوابة التحديث الأصلية. وجودها في القائمة لا يعفيها ولا يجعلها مكتملة. إضافة هويات إلى محرر Studio تنتظر تنفيذ fixture حقيقية ومراجعة عقده بصورة منفصلة.

كل سجل يبدأ بـ`reviewDecision: not-reviewed` و`casesMapped: false`، دون مرجع أو تصوير أو ناقدين. الناتج `complete: false` و`accepted: 0` مقصودان. نجاح اختبار هذا المشغّل لا يعني نجاح الواجهات جرافيكيًا.

## وحدة المراجعة

كل قرار يخص حالة واحدة محددة، لا متوسط شاشة أو لعبة:

```js
{
  schemaVersion: 1,
  screen: 'ersomha.draw.guesser',
  state: 'draw-connected',
  role: 'guesser',
  locale: 'en',
  viewport: { width: 390, height: 844 },
  source: { revision: '<40 hex Git SHA>', fingerprint: '<64 hex snapshot SHA>' },
  authorIds: ['designer'],
  reference: {
    id: 'approved-drawing',
    artifact: { path: 'evidence/reference.png', sha256: '<64 hex>' },
    targets: [/* contexts explicitly covered by this approval */],
    approval: {
      status: 'approved', kind: 'user', actorId: 'owner',
      evidence: { path: 'evidence/user-approval.json', sha256: '<64 hex>' },
      approvedArtifactSHA256: '<approved reference artifact SHA>',
      approvedTargets: [/* exact contexts covered by this approval */]
    }
  },
  evidence: {
    kind: 'browser', actualComponent: true, syntheticData: true,
    runner: 'actual-component-fixture', capturedAt: '<ISO timestamp>',
    artifact: { path: 'evidence/capture.png', sha256: '<64 hex>' },
    context: {/* exact screen/state/role/locale/viewport */},
    source: {/* exact revision and fingerprint */},
    referenceSHA256: '<approved reference artifact SHA>'
  },
  critics: [/* exactly two different independent reviewers */],
  approvedDeviations: []
}
```

يحتوي كل ناقد على `reviewerId` و`discipline` و`decision: accept` و`report` (path/sha256) و`subject` و`findings`. يلزم ناقد فن `art` وناقد تجربة استخدام `ux`، وليس شخصين من الاختصاص نفسه. يطابق subject السياق والمصدر وبصمتي المرجع والتصوير. معرفات المؤلفين والنقاد معرفات مستقرة صغيرة الأحرف؛ لا يُسمح بأن يكون الناقد مؤلفًا أو أن يُكرر نفس المعرف. لا يستطيع هذا العقد اكتشاف شخص يستخدم هويتين مستعارتين؛ يراجع قائد الفريق استقلال الهوية والاختصاص الفعليين.

كل finding يحتوي id وsummary وpriority من P0 إلى P3 وstatus من open/resolved وblocking كقيمة منطقية. لا يمكن اعتماد P0/P1 المفتوح أو أي finding مانع صريح. وضع resolved يحتاج resolution.evidence وبصمة التصوير الذي يثبت الإصلاح. أما الفرق البصري غير المانع P2/P3 فيحتاج approvedDeviation تربط الناقد والملاحظة وسبب الاستثناء وموافقة المستخدم ونفس subject الحالي. الاستثناء القديم أو العام لا يصلح.

مسارات artifacts نسبية إلى حزمة الدليل؛ لا مسارات اجتياز أو روابط تحمل صلاحيات. لا توضع كلمات ارسمها الخاصة أو أدوار مافيا أو بيانات حسابات حقيقية في الأدلة العامة؛ تستخدم المراجعات fixtures اصطناعية معلنة، أو أدلة خاصة محمية عند الحاجة.

## القبول مغلق افتراضيًا

`evaluateVisualReview(record)` تعيد accepted فقط إذا اجتمعت كل الشروط:

1. مرجع محدد وبصمة وموافقة مستخدم موثقة تربط `approvedArtifactSHA256` ببايتات المرجع و`approvedTargets` بالسياق الحالي صراحةً؛ تبديل المرجع أو توسيع نطاقه يحتاج موافقة جديدة.
2. لقطة من المكون الحقيقي في متصفح أو غلاف أصلي، وليست صورة تصور؛ مع تصريح واضح بوجود بيانات اصطناعية.
3. تطابق الشاشة والحالة والدور واللغة والمقاس ونسخة المصدر وبصمة العمل غير الملتزم.
4. ناقد فن وناقد تجربة استخدام مستقلان عن المؤلف وعن بعضهما، وكلاهما يقبل نفس الدليل الحالي.
5. لا ملاحظات مانعة مفتوحة، ولا فروق غير معتمدة أو إصلاحات بلا دليل.

أي نقص يعيد blocked مع أسباب؛ لا درجة متوسطة ولا إجماع ضمني ولا fallback من تصوير حالة أخرى. هذا فاحص عقد الأدلة، لا محرك رؤية يقرأ الصور، ولا توقيعًا تشفيريًا من المستخدم أو المراجعين. على مشغّل الالتقاط حساب البصمات من البايتات الفعلية وعلى المراجعين فتح الأدلة؛ صحة صياغة JSON وحدها لا تثبت تلك الوقائع.

## مصفوفة العمل والمسؤوليات

الحالات تُربط أولًا بالدور: مضيف/ضيف، رسام/مخمّن، مالك/زائر، ودور مافيا المسموح. يفرّق state صراحةً بين البيئات والإتاحة والتحميل/الفراغ/الخطأ/الانقطاع/لوحة المفاتيح/المكالمة إذا تغير العرض. اللغة العربية والإنجليزية مستقلتان عن لغة محتوى الغرفة. لا تقبل حالة افتراضية مبهمة بدل هذه الفروق.

مقاسات التخطيط الأولية:320×568،360×800،390×844،430×932،844×390،1024×768، في Chromium وWebKit. توضع اختبارات حجم النص وتقليل الحركة ومناطق الأمان كحالات صريحة إضافية. بوابة التحديث الأصلية تحتاج تصويرًا أصليًا؛ تمثيلها داخل المتصفح لا يثبت عرض Swift. الصور الثابتة لا تثبت الحركة أو النقر أو التمرير: ترتبط تقارير التفاعل بالدليل، ويتحقق القائد من الاختبارات العملية دون force.

مسؤول الجرد يملك هذا السجل والفرق بين مجموعاته. المصمم يملك المرجع ودفعة التصورات. منفذ الواجهة يملك المكون وCSS الخاص به ويحفظ عقود الألعاب والحفظ والهوية والخصوصية. مراجعان مستقلان يفحصان كل قرار؛ قائد الفريق يدمج الأدلة ويمنع ترحيل قبول قديم إلى نسخة جديدة. لا يغيّر المصمم ملفًا مشتركًا يملكه منفذ آخر في نفس الدفعة.

تبقى عقود editor IDs وطرق act والـstorage/content IDs والأسعار والمقتنيات والصلاحيات كما هي. لا إضافة خدمات خلفية أو إطلاق مافيا أو الإنجليزية الأونلاين العامة ضمن هذا العمل. لا نشر أو إرسال App Store.

اعتمد المستخدم صراحةً اللافندر `#EFD3FA` وخطة تحديث متوافق وتنفيذها محليًا: «أعتمد اللون والخطة والتنفيذ المحلي». يسجل `drawing-color-approval.json` ضمن حزمة أدلة Batch03 الموافقة ومرجع المقارنة. هذه موافقة محددة على تحديث عقد الألوان الضروري للمظهر، ولا توسع تفويض النشر أو تشغيل الميزات المغلقة.

- لا يعرض العميل اللون الجديد قبل تأكيد دعم الغرفة ومزامنة اللوحة؛ النسخ المجهولة أو المتعارضة تمنع الحبر وتطلب استعادة محدودة دون استبدال اللون. الأوامر المتأخرة لا تغيّر لوحة أحدث، والمزامنة الصحيحة تحرر ضغط اتصال سابقًا.
- دليل `drawing-integration-v2-final` يثبت دورين عبر خادم محلي فعلي لكل من Chromium وWebKit، مع قياس اللون في رسم اللاعب المستلم. نقل صوت LiveKit محاكًى. لا يُستنتج من ذلك نجاح IPA قديم أو جهاز فعلي أو نشر إنتاجي.
- تقارير المراجعة محددة ببصمات مصدرها؛ قبول توافق اللون لا يغلق القبول الفني العام لارسمها أو بقية الألعاب.

شملت الفئات الجديدة `general` و`capitals` و`food` و`fruitsveg` و`tech` و`apps` و`brands` و`cars` و`shopping`. مع الرسوم الخمسة السابقة، يصل مجموع فئات B المرتبطة إلى 14 من 78. تستخدم الفئات الـ64 المتبقية مصادر عرضها الموجودة إلى أن تُعتمد وتُنتج أصولها.

يضم دليل المتصفح الإعداد الحقيقي بالعربية والإنجليزية في Chromium وWebKit وبعروض 360 و390 و430، مع اختبار اختيار الفئات وحفظها في مباراة محلية. يثبت اختبار الغرفة على الخادم المحلي عرض الأصول من جهازين واستمرار مسار الحكم والاستئناف. البصمات وأوزان الصور وعمليات التوليد محفوظة في سجل الأصول ضمن مجلد التسليم `batch-03/production-assets/category-nine`.

## متابعة الإعدادات والمكالمات والحساب والصانع

اعتمد عبدالله اللوحات 04 و06 للمكالمات، و05 للإعدادات، ثم 07 للحساب و08-v3 للشروط و09 للوحة الصانع. يسجل ملف `approved-followup-2026-11-19.json` الصور السبعة المعتمدة، بما فيها لوحة 10 لمراجعة صور البروفايل والأغلفة، مع بصمة كل صورة ورد الاعتماد.

تجمع الإعدادات لغة الواجهة وحالة الحساب، وتعرض الصوت والعرض والخصوصية داخل مساراتها الحالية. في المكالمات يظهر المتحدث والطي وحالة الميكروفون، ويبدأ الشريط العائم بجوار بطاقات اللعب. يطابق حقل الشروط الاختيار الصريح، ويعيد زر الموافقة طلب الحفظ عند فشله. تستعمل نسخة الحساب حالة الاشتراك والاستحقاق الحالية، وتعرض لوحة الصانع إحصاءات مجمّعة للبيئة المحددة.

تستخدم قائمة صور الصانع نفس آلية مراجعة الصور في الإدارة. يتحقق العميل من هوية الصانع الحالية ثم من صلاحية المراجعة الحالية قبل جلب الطلبات. يُرسل القرار عبر المسار القائم ومعه نسخة الصورة وسبب القرار. الاختبارات الخاصة بالمراجعة تستعمل حسابات ومقتنيات وصورًا اصطناعية محلية.

يحفظ معرض المقارنة اللقطات والبصمات ومراجعات الفن والاستخدام لكل دفعة. يبقى الجرد مفتوحًا للحالات التي تحتاج مراجع أو دليل تشغيل، وتحتاج المكالمات والميكروفون واللمس إلى تحقق على الهواتف.

اعتمد عبدالله أيضًا اثني عشر رسمًا إضافيًا لبديهة، مع رسم الجدة والطفل من الملحق لفئة الأمثال. رُبطت أصول WebP الجديدة بمعرّفات الفئات القائمة في باقة المقاسات 128 و256. تغطي أصول B المربوطة 26 فئة حتى هذه المرحلة. اختبرت رحلات العربية والإنجليزية الانتقال من البطاقة إلى لوحة اللعب، وحفظ المعرفات المختارة من الجلسة المحلية. ظهر الرسم أيضًا في الخيار واللوحة عند تشغيل مباراة غرفة عبر الخادم المحلي.

## اكتمال رسوم فئات بديهة

اعتمد عبدالله دفعة الفنون والمهارات ذات 24 فئة ثم الدفعة الأخيرة ذات 28 فئة. تكمل 52 صورة أصلية تغطية فئات بديهة الـ78 في الفهرسين. يرتبط رسم الخزنة بفئة الشفرة، وآثار الطريق بالسيرة النبوية، ونظارات المختبر ببريكنغ باد، واللفافتان بجوجوتسو كايسن وفق ملحقات الاعتماد. تحفظ مجلدات أدلة الدفعتين الصور والمعرّفات والمطالبات وبصمات المصدر والتصدير.

تعمل ملفات 128 و256 بكسل مع مسارات عرض الاختيار واللوحة الحالية. تُثبَّت الملفات المبصومة مع غلاف عامل الخدمة، فتُعرض الفئات في مباراة عربية محلية بعد انقطاع الشبكة. تُحفظ حزم المحتوى الإنجليزية وفق مسارها القائم عند الطلب. أثبتت مقارنة مصدر التشغيل تطابق كل ملفات `src/data` مع نسخة المعاينة السابقة.

بعد اكتشاف تغطية اختصارات الإعداد، يأخذ الدليل المثبت موضعه تحت شريط اللعبة ومنطقة الأمان، وتُحسب مسافة القفز إلى القسم. يدخل الدليل التمرير العادي في الارتفاع القصير أو وضع النص المكبّر. يحافظ ارتفاع سطر شارة الاختيار على تمركز الرقم عند 200%. تتضمن أدلة الحزمة إعادة التحقق من القفز والنقر والتركيز والاستئناف، ولقطات للفئات الـ78 في بطاقات حقيقية ولوحات اللعب على المحركين.

يحفظ إعداد بديهة وتذييل اللوحة مساحة فاصلة عن زر «اللّمة»، مع حساب مساحة الأمان السفلية. عند تكبير النص ترتب الشاشة البطاقات في عمود وتعيد توزيع أوامر اللوحة. في العرض القصير مع النص المكبر يتبع التذييل التمرير حتى يمكن الوصول إلى آخر سؤال. تُترجم أفعال تأكيد الإنهاء في اللغتين، وثبت فتحه وإلغاؤه بالنقر العادي والتراجع بعد حكم السؤال.

اعتمد عبدالله لوحات B للإقلاع والتعافي ورمز الهدية وخيارات المحادثة. يغطي سجل الجولة 11 حالة بتصميم مرجعي وبصمة لقطة ومصدر وحكمين مستقلين. تقع أدلة الجولة ومعرضها في مجلد `secondary-surface-implementation` ضمن مجلد تسليم التصميم.

يعرض الإقلاع حالة تجهيز الصور وإعادة المحاولة والإشعار بعد الدخول. يستخدم التعافي إجراءات كل نطاق. يمكن إعادة بدء المباراة بعد مسح حفظها المحدد، وتتيح اللّمة العودة إلى الرئيسية إذا استمر العطل. يحتفظ مسح بيانات الجهاز بجلسة الحساب.

تُتحقق الهدية على الخادم وتظل مرتبطة بالحساب. تستخدم خيارات المحادثة الفردية والشلّة المعالجات الحالية للدعوة والكتم وإدارة الأعضاء والأفعال الحساسة. يظل الإلغاء ممكنًا أثناء إشعار تفعيل الهدية، ويستعمل حركة إغلاق الورقة المشتركة.

أُخذت لقطات الإقلاع والهدية وخيارات المحادثة من الحزمة المحلية الفعلية. اختُبر طلَب الهدية وقراءة الاستحقاق والكتم في خادم محلي بحسابات اصطناعية. تُختبر حالات التعافي بمكونات المصدر نفسه مع أعطال تصيير اصطناعية. يبقى جرد الواجهات العام واختبار الهواتف الفعلية منفصلين عن قبول هذه الحالات.
