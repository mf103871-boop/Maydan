# Mafia rating evidence, candidate policy and future season binding

Updated 2026-10-30, Asia/Amman. This implements the engineering path for E2. It does not assert that real human calibration has been completed. No new tests or data collection were executed while implementing this path. The integration chat must test these modules, the SQL, authorization and all race/retry cases before acceptance.

## Preserved current season

`preview-elo-1` continues to dispatch to the exact existing `rankedMatchDeltas` algorithm. Its existing season and settings are unchanged. `faction-elo-2` is a separate explicit policy with a learned faction intercept, the same 400-point Elo scale, ten placement games and team transfer budgets 32/16. A learned policy can be bound only to an existing future ruleset-1 season before its start and before any queue or match exists. A current season cannot be silently recalibrated. The old `rating_model` column remains the engine-family compatibility marker; the separate binding is the effective versioned policy. Client projections and frozen result metadata must use the resolved effective model for a future bound season.

`ratingDeltasForPolicy` validates the eight-seat six-town/two-Mafia template, uses the faction intercept with the two team rating means, and distributes one integer team transfer with deterministic remainder allocation. Ordinary transfers conserve the total before floor/ceiling; an explicit forfeiter loses at least sixteen points. The rating range is 0–3000. Natural elimination retains the result. No inactivity decay is applied. A technical abort has zero rating effect, while a match completed textually is a normal result. These are versioned policy choices, not conclusions from absent telemetry.

## Bounded export without personal content

`scripts/mafia-rating-calibrate.mjs --export-plan <new-file.json>` creates a read-only query plan. It never runs Cloudflare, uses credentials, makes a network call or mutates a database. A separately authorized operator can execute the plan against the exact reviewed preview database and save its JSON result. Migration 0025 must already exist because the query excludes seasons with a learned-policy binding.

The query returns at most 1000 chronological aggregate match rows from unbound v1 seasons: a private source reference, time, result, two team means, number of forfeits, net rating change and receipt count. It exports no account or seat IDs, individual roles, room code, token, chat, voice or provider metadata. Its `allHuman` field is always false. Human participation cannot be inferred from WebSockets or a result receipt.

To wrap a saved export, use `--wrap-export <ledger-result.json> --provenance <provenance.json> --output <new-dataset.json>`. The provenance object contains the source commit, Worker version, migration-set SHA-256, query SHA-256 and export timestamp; obtain them from the actual frozen release receipt and exported query plan. Optional `--evidence-kind` defaults to `unknown`. Wrapping always resets human labels to false. Only an operator who reviewed actual human session evidence may subsequently attest `evidenceKind: real-human` and mark the verified rows `allHuman: true`. Keep detailed session evidence private and separate. Synthetic or unknown data can produce diagnostics but cannot produce a publishable policy.

The JSON contract is `rating-dataset.schema.json`. Unknown fields, duplicate references, oversized input and invalid numeric ranges are rejected. Local artifact writes are exclusive and never silently overwrite an existing file. Raw ledger exports and datasets are private operator material. Only the aggregate report and policy candidate should be shared for review.

## Reproducible fit and aggregate report

Use `--input <dataset.json> --output <new-report.json> --candidate <new-candidate.json>`. The CLI validates and canonically sorts the data, records its SHA-256, splits eligible rows chronologically 80/20, and fits only a faction intercept on the training set with a Beta(1,1) regularizer. It does not fit on the holdout. It computes baseline and candidate Brier scores, five probability calibration bins, observed faction outcomes, a 95% Wilson interval for decisive outcomes, sample/exclusion counts and net-rating inflation summaries. Reports contain no per-match references or source row arrays.

Initial proposal gates are at least 100 verified-human, eight-receipt, non-forfeited, non-aborted matches; at least 80 training and 20 holdout matches; a decisive faction Wilson half-width at most 0.1; a fitted equal-rating town prior in 0.2–0.8; the expected export query hash; and no holdout Brier degradation larger than 0.02. These are review gates for an initial candidate, not proof of fun, understanding, unbiased matchmaking, independence of repeated players, correct rank boundaries or complete human balance. Repeated-player population analysis and comprehension remain part of D3. Draws participate in the score fit as 0.5; the Wilson summary is explicitly decisive-only.

Without adequate actual samples the output is `insufficient-evidence`, includes blocker codes, and contains no usable policy. Sufficient supplied samples produce `candidate-needs-review`. Every report keeps `calibrated:false`, `ready:false`, `liveVerified:false` and `evidenceAuthentication:operator-supplied-unverified`. The tool never invents matches, creates a calibrated label or activates a policy. Individual floor/ceiling attribution cannot be reconstructed from team aggregates, so the report labels that inflation limitation explicitly.

## Authorized publication and immutable binding

`POST /api/mafia/rating-policy` accepts `{dataset, reviewAcknowledged:true}`. The helper requires the exact preview origin, the ranked flag, a current non-suspended moderator session and rate limiting. It recomputes the report and proposed prior on the server; the client cannot directly submit a rating prior or a policy. Every aggregate is compared to the actual preview ledger, and the same ledger and live-session predicates are repeated inside the immutable insert. A mismatched or deleted receipt set cannot support publication. Human labels remain an explicit moderator attestation and are not independently authenticated by the ledger.

The stored status is `reviewed-supplied-evidence`. It stores only the canonical policy, aggregate report, provenance hashes, reviewer reference and time. It never stores the private dataset or a raw source match reference. Repeated identical publication returns the same hash-keyed artifact. Policy JSON and its SHA-256 are verified before binding or use.

`POST /api/mafia/rating-policy/bind` accepts `{seasonId,policyId}`. Its conditional insert requires a future open season, no existing queued account or match for that season, the existing fixed template and current moderator session. A season can receive only one binding. An identical retry returns the existing binding; a different policy conflicts. It cannot replace the policy of an active or historical season. `resolveMafiaSeasonRatingPolicy` returns the exact v1 descriptor for an unbound season and verifies the canonical policy digest for a bound one. There is no endpoint for editing or deleting a published policy or binding.

Migration `0025_mafia_rating_policy.sql` creates the two additive tables. Reviewer references use `ON DELETE SET NULL`; `mafiaRatingPolicyDeleteStatements` also provides explicit nulling for account-deletion transactions. The published evidence and policy remain reproducible after account deletion. No production setting, current season, rank band, reward policy or existing receipt is changed by publication.

The seeded preview contains no future season factory. Creation of a subsequent season is an explicitly reviewed operator task with fixed dates and rewards; the binding endpoint does not invent or open a new season. The current preview can therefore keep running v1 while real data is collected and reviewed for the next season.
