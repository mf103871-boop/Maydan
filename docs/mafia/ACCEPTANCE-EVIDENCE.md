# Mafia acceptance evidence contract

Updated 2026-10-30, Asia/Amman. Engineering of the plan and acceptance of a frozen release are separate. `scripts/mafia-acceptance-report.mjs` evaluates supplied evidence without running tests, accessing accounts/providers, deploying, changing flags, reading credentials or writing files. The destination Maydan chat can run the new candidate's checks, collect authorized evidence and evaluate it. This implementation has no new test execution attached.

```
node scripts/mafia-acceptance-report.mjs --candidate candidate-receipt.json --manifest local-manifest.json --evidence private-evidence/acceptance.json --calibration private-evidence/rating-calibration.json
```

Generate `local-manifest.json` with the existing read-only preview manifest command and current migration ledger. The candidate receipt must identify the exact isolated preview, clean source commit, actual Worker version, artifact hashes, configuration hash, migration-set hash, rules and successful hosted/local byte correspondence. A historical A–D receipt or old 1715-test result does not cover a new candidate. Add `nativeBuild` as a nonempty version/build string and `nativeIndexSHA256` as the actual bundled native HTML hash only after updated native delivery from the same source is recorded; the normal web-only receipt intentionally has no such identity. Native packaging selects an explicit preview API origin and can differ in bytes from the hosted same-origin HTML.

Copy `acceptance-template.json` into a private directory outside source, bind its candidate fields to the frozen receipt and populate only observations that actually occurred. The template represents missing evidence and cannot pass. Output includes fixed blocker codes, counts and candidate hashes, without private artifact content or device aliases. Exit code 2 means incomplete supplied evidence, 1 means malformed/unavailable input, and 0 means complete, structurally consistent supplied evidence. Output **always** keeps `ready:false`, `liveVerified:false` and `physicalHumanClaimsAuthenticated:false`: file hashes do not authenticate physical devices, real humans, provider entitlements or operator decisions. A release remains a separate reviewed action.

## Artifacts

Each artifact metadata row has `id` (short lowercase alias), `path` (`artifacts/name.json` under the evidence directory), `sha256`, `kind`, and ISO `capturedAt`. Kinds are `automated-run`, `device-observation`, `human-session`, `balance-review`, `provider-quota`, `performance`, `rating-review`. Files must be nonempty, regular nonsymlink files, at most 1 MiB each and 8 MiB combined, with at most 64 artifacts. The evaluator hashes bytes and never displays their contents. JSON inputs are bounded to 1 MiB, depth 16 and 20000 nodes; unknown evidence fields are rejected. Relative paths cannot escape the evidence directory. Keep source logs, credentials, room codes, account/session IDs, private chat, audio, identity documents and live role captures out of the evidence bundle. Sanitized research observations can refer to local anonymous aliases only.

Artifact JSON is a sanitized receipt, not an arbitrary renamed log: `{schemaVersion:1,kind:'mafia-acceptance-artifact',type,candidate:{sourceCommit,indexSHA256,workerVersion},capturedAt,observations}`. Its type/time must match metadata and all three candidate fields must match the current receipt. Every nonempty observation has only `check`, `status`, `triggerCode`, `outcomeCode`, `counts`, `measurements`. Codes are short lowercase aliases; statuses are pass/fail/not-run; the last two fields are small maps of nonnegative integer counts and finite nonnegative measurements. No free chat/log text belongs in this contract. Use each required scope/case ID as its observation `check`; automated scopes and device cases need corresponding pass observations, not only a top-level declaration. Preserve original restricted runner/operator records separately for the human reviewer. An old raw 1715-test log cannot satisfy this receipt schema or candidate binding.

## Current-candidate automated checks

`automation` has `sourceCommit`, positive integer `passed`, zero `failed` and `skipped`, `scopes`, `artifactIds`, and ISO `completedAt`. Evidence and artifacts expire after seven days. Required scopes are exported as `MAFIA_ACCEPTANCE_SCOPES`: rulesets, D1 ledgers, account deletion, identity epochs, skill matchmaking, ranked settlement, season closure, community grants, tournament roster, tracker interactions, voice authorization and responsive browser behavior. Counts and declared scopes require their actual matching sanitized run report; declaring them does not make this tool authenticate the runner.

## D2: physical and native matrix

Each `devices` row has `alias`, `hardwareAlias`, `kind`, `platformVersion`, `clientVersion`, `indexSHA256`, and `nativeBuild` (null for a browser). Kinds are `physical-iphone-safari`, `physical-iphone-native`, and `independent-browser`. Use two different hardware aliases for the physical iPhones, and reuse the respective hardware alias for that phone's Safari and native rows. Browser hashes match the candidate's `indexSHA256`; native rows match its separately recorded `nativeIndexSHA256` and actual updated native build. Simulator/WebKit emulation is not one of these physical kinds.

Each case in the template records `pass`, `fail` or `not-run`, the device aliases actually observed, hashed observation artifact references, `observedAt`, `unauthorizedAudienceCount`, and `duplicateAuthoritativeRewardCount`. Every required case needs both physical iPhones in Safari and the updated native app plus the independent browser, zero unauthorized audiences and zero duplicate authoritative rewards. The human readable trigger and sanitized observation belong in its referenced observation artifact. Evidence expires after thirty days. Preserve failures; a fixed candidate needs matching new evidence rather than silently changing a failed row to pass.

## D3 and G1: actual human samples

Each `humanSamples` row records `capacity`, `mode`, `rulesetVersion`, `participantKind`, integer `completed`, `groups`, `novices`, `returning`, `understandingParticipants`, `correctWinCondition`, `artifactIds`, and `observedAt`. Synthetic and mixed samples do not satisfy human gates. For ruleset 1 require at least three completed real-human matches at every supported size 6–12, with classic for 6–8 and Shadow for 9–12. Seven players require at least ten completed matches from at least two independent groups. These are initial research minimums, not statistical proof of balance. The aggregate comprehension pilot needs at least ten participants and at least 80% correctly explaining the win condition. Only count each participant/match in the intended cohort; aliases in research artifacts help a reviewer detect repeated data.

`balanceReview` has all thirteen role IDs in `rolesCovered`, `sevenPlayerReviewed:true`, zero `blockingIssues`, referenced balance-review artifacts and `reviewedAt`. Tracker ruleset 2 additionally needs at least three completed real-human matches with eight or more players and its own sample references. Ruleset-1 human samples expire after ninety days and the tracker/review evidence after thirty, while still binding to the exact candidate in the envelope. Quantitative faction calibration uses the independent calibration tool; these pilot counts do not calibrate a rating model.

## A5 and performance

`providerQuota` has `provider:'livekit'`, integer `participantLimit`, `roomLimit`, `mafiaReservedParticipants`, `mafiaReservedRooms`, `socialReservedParticipants`, `socialReservedRooms`, `artifactIds`, and `capturedAt`. Actual provider entitlement evidence must be no more than seven days old. Mafia reservations must cover the reviewed manifest ceiling; social reserves need at least one twelve-person call/room. Provider totals must cover both reservations. Configuration values alone do not establish entitlement, and this evaluator does not read a provider account.

`performance` has nonnegative measured `networkRttMs`, `actionAckP95Ms`, `audioTransitionMaxMs`, `queueWaitP90Ms`, integer `actionSamples`, `audioSamples`, `queueMatches`, `artifactIds`, and `capturedAt`. The controlled-network gate requires RTT ≤150 ms, action ACK p95 ≤300 ms from at least 100 commands, actual audible safe transition ≤3000 ms across at least twenty transitions, and populated-queue wait p90 <90000 ms over at least ten matches. Separate other network conditions. Evidence expires after fourteen days.

## E2: calibration and separate review

The calibration report contract comes from the read-only calibration tool: `kind:'mafia-rating-calibration-report'`, schema 1, real-human evidence, matching source, ruleset 1 and classic8 template, baseline `preview-elo-1`, a `candidate-needs-review` status without blocker codes and a candidate policy hash. That status is deliberately not an automatic calibration or activation claim. `ratingReview` binds the exact report file hash and policy hash, a recorded `decision:'accepted-for-next-preview-season'`, hashed review artifacts and `reviewedAt`. Both engineering output and a separate review record are required. Never rewrite the running season's frozen policy from a report; any accepted policy belongs to a separately created/frozen future preview season.
