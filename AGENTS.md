# Maydan repository handoff

- Start with [`CURRENT-RELEASE.json`](CURRENT-RELEASE.json) and [`docs/releases/CURRENT.md`](docs/releases/CURRENT.md). They distinguish the current development source, signed TestFlight artifact, preview and published game.
- Fetch and inspect `origin/main` before starting new work. Preserve existing local changes; do not reset, clean or overwrite an old checkout to make it current. A dated worktree or branch is not the current release just because it contains a newer-looking local file.
- Build 1.9 (60) is already uploaded and available internally. Its immutable source is recorded in the release manifest. Later documentation commits do not change that IPA. Verify subsequent changes instead of claiming they are included in an older build.
- `ios/app-store.json` and the checked-in Xcode marketing/build values contain historical setup defaults. They do not report the latest Apple build. Native releases use explicit version, build, environment and release-profile inputs; read Apple's current build/upload inventories before reserving a number. Do not upload build 60 again.
- The current preview is `https://maydan-mafia-preview.mf103871.workers.dev/`. `maydan-game` is production; do not replace production links in legal/support documents with preview links. Localhost, GitHub Pages and old audio/Plus labs are not the current integrated preview.
- A merge to `main` is not permission to deploy production, submit publicly, raise the minimum supported version, invite testers, alter signing or run remote migrations. Follow [`docs/releases/production-paired-release.md`](docs/releases/production-paired-release.md), check the live build trigger before a merge, and preserve the build-only deployment command. Never use a generic Wrangler deployment to replace live resources or the private Ersomha word bank.
- Private Warmth audio remains an encrypted internal-preview asset. Do not upload decrypted files, signing material or provider secrets to GitHub, Workers static assets, Pages or public evidence. Old one-shot operators and apply locks are historical records; do not modify, delete or retry them.
- Keep `CURRENT-RELEASE.json` and its human-readable handoff current when a newer verified release is delivered. Record what was tested separately from physical-device, real-ad/SSV and public-release acceptance.
